# Doc writing

Write in the user's language. A spec in `docs/features/` follows the `feature-spec` skill first; this skill covers its figures.

## Place and name

- Placement (one module or several): see Docs placement in `CLAUDE.md`. A topic goes in `docs/<domain>/`, its figures in `docs/<domain>/img/`. File names in kebab-case, after the subject.
- Link each sheet to its sister sheets, and state its prerequisites at the top.
- Check that the target is versioned (`git check-ignore -v <path>`). If git ignores it, say so: a doc for the team in an ignored folder exists on one machine only.

## Concept sheet

```markdown
# <Subject>

<One framing line: audience, prerequisites, sister sheets.>

**In one sentence:** <the shortest correct definition>

## <The concept>          what it is, what it is made of
## Why it matters          the concrete stake; a table for parallel cases
## Pitfalls                what misleads in practice
## Vocabulary              one line per term
```

Drop the sections that do not apply. Genetics sheets go in `docs/genetic/concepts/` (`genetician` agent), and the sheet that traces the same concept in the code goes in `docs/genetic/stack/`, under the same file name (`stack-genetician` agent). Each links to the other.

## Diagram medium

| Medium | For | Why |
|---|---|---|
| Mermaid, in the Markdown | flows, decision trees, hierarchies | renders on GitHub and in IDEs, diffs as text |
| SVG, `img/<name>.svg` called as `![](img/<name>.svg)` | geometry: what must align, pair or keep its proportions | full control, sharp at any size |
| Monospace, in a fenced block | aligned sequences, codons, columns | clearer than any drawing for a character alignment |

Never an image generated by a model: it invents the labels, and in a technical sheet the labels are the content.

## Figure rules

- A figure carries labels and a legend only. Explanations go in the Markdown. When you move text out of a figure, check that the Markdown has it.
- Never colour alone: pair it with a letter, a symbol or a label.
- Each SVG has a `<title>` and a `<desc>`. GitHub does not render an SVG inline in Markdown: always a separate file.
- When you remove content from an SVG, reframe the `viewBox` and the background `<rect>`.

## Check each figure by rendering it

Do not deliver a figure that you have not looked at. Write it, render it to `tmp/doc-render/`, read the PNG, fix it.

- **SVG:** `xmllint --noout <file>.svg`, then Chrome headless at 1× (`--window-size` = the `viewBox` size): `"<chrome>" --headless --disable-gpu --hide-scrollbars --screenshot=tmp/doc-render/<name>.png --window-size=<W>,<H> "file://<abs path>.svg"`. Chrome's path depends on the OS.
- **Mermaid:** copy the block to `tmp/doc-render/<name>.mmd`, then `npx -y @mermaid-js/mermaid-cli -i tmp/doc-render/<name>.mmd -o tmp/doc-render/<name>.png`.

In your report, say which figures you checked by rendering and which you only wrote.

## Palette

Pastel fills, text `#33404f`, a stroke in the same hue. Colour by semantic role, never to decorate.

| Role | Fill | Stroke |
|---|---|---|
| decision (diamond) | `#fbf1cd` | `#ddc46a` |
| DNA, nominal path | `#cfe3f5` | `#6fa8d6` |
| RNA | `#cfeae7` | `#6fb5ad` |
| protein, special case | `#e2d9f3` | `#a08cc9` |
| favourable outcome | `#d4ecd7` | `#7cb98a` |
| unfavourable outcome | `#f8d7da` | `#d98a91` |
| exception to isolate | `#fbe0cd` | `#e0a877` |
| neutral, entry point | `#eef1f5` | `#aab3c0` |

In Mermaid: `style <id> fill:#cfe3f5,stroke:#6fa8d6,color:#33404f`. Nucleotides follow IGV, as the portal's viewer does: A `#1a9641`, C `#2c7bb6`, G `#e08214`, T `#d7191c`.

## Accuracy

- Invent no technical fact. Cite each claim about the code as `path/file.ext:line`, checked by reading it. Otherwise, write that you did not find it.
- When you cite a module, note its commit SHA and the date: a checkout can lag behind, and a `file:line` goes stale silently.
- Correct what you know is wrong in content that you are given, and say so.

## Never

- Commit or stage: report the files that you wrote.
- Publish outside the repo (artifact, upload).
- Read patient data, files that look like they hold PII, or `.env` files (`confidentiality` rule).
- Attempt complex geometry (curves, projections, dense layouts) without saying so: offer to rerun with Opus.
